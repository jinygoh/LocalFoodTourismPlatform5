# TasteLocal Application Issue Log

This document logs the issues discovered during the testing of the TasteLocal application, along with an impact analysis and a plan for corrective action.

| ID  | Issue Description                                                              | Severity | Impact                                                                                                | Corrective Action Plan                                                                                                                                                                                                                                                         | Status      |
| --- | ------------------------------------------------------------------------------ | -------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- |
| 1   | **End-to-End Tests are Unstable**                                              | `High`   | The inability to reliably run E2E tests means there is no automated way to verify that critical user flows are working correctly. This increases the risk of regressions and makes the development process less efficient. | 1. **Investigate Test Environment:** Dedicate time to thoroughly investigate the E2E test environment to identify the root cause of the timeouts. This may involve experimenting with different server configurations, Playwright settings, and database setup for tests. <br> 2. **Refactor Tests:** Review and refactor the existing E2E tests to be more resilient. This includes using more robust selectors, adding explicit waits where necessary, and breaking down long tests into smaller, more focused tests. <br> 3. **CI/CD Integration:** Integrate the E2E test suite into a CI/CD pipeline to ensure that tests are run automatically on every code change. | **`Open`**  |
| 2   | **Missing Test Coverage for Favorites Feature**                                | `Medium` | The "Favorites" feature is a key part of the tourist user flow, but it is not currently covered by any automated tests. This means that bugs in this feature could go unnoticed. | 1. **Write Unit Tests:** Write unit tests for the `toggle_favorite_api` view to ensure that it correctly handles adding and removing favorites. <br> 2. **Write E2E Tests:** Create a new E2E test that simulates a user adding and removing items from their favorites and verifying that the changes are reflected on their profile page. | **`Open`**  |
| 3   | **Vendor Profile Management Not Tested**                                       | `Medium` | The ability for vendors to manage their business profile is a core feature for vendors, but it is not covered by any automated tests. | 1. **Write E2E Tests:** Create a new E2E test that simulates a vendor logging in, navigating to their dashboard, editing their profile, and verifying that the changes are saved. | **`Open`**  |
| 4   | **Hardcoded URLs in E2E Tests**                                                | `Low`    | Some of the initial E2E tests contained hardcoded URLs, making them brittle and difficult to maintain. | The identified tests have been updated to use the `live_server` fixture and Django's `reverse` function to dynamically generate URLs. Future tests should follow this pattern. | **`Closed`**|
